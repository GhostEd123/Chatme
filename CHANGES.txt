NEW FILE: src/core/lib/apiClient.ts
────────────────────────────────────────────────────────────────────────────────

Purpose:
  A thin fetch-based HTTP client used by all React Query hooks instead of
  axios. Handles authentication and token refresh transparently.

Key behaviours:

  1. Auto-attaches the Authorization header
     Every request (unless skipAuth: true is passed) reads the current
     accessToken from authStore and sets:
       Authorization: Bearer <token>

  2. Automatic 401 → token refresh → retry
     If the server responds with HTTP 401, apiClient calls a private
     refreshAccessToken() function which:
       a. Reads the refreshToken from authStore.
       b. POSTs to /auth/refresh.
       c. On success: calls updateAccessToken() in authStore and retries
          the original request with the new token.
       d. On failure: calls clearSession() to log the user out.

  3. ApiException class
     If the response is still not OK after the refresh attempt, it throws
     an ApiException with { status, code, message } so React Query
     can surface the error correctly.

  4. 204 No Content support
     Returns undefined for 204 responses (used by logout and delete
     endpoints) without attempting to parse JSON.

  Usage:
    apiRequest<T>(path, { method, body, headers, skipAuth })

NEW FILE: src/core/lib/socketService.ts
────────────────────────────────────────────────────────────────────────────────

Purpose:
  A singleton class (exported as socketService) that owns the one and only
  Socket.IO connection for the entire app lifetime. Screens and hooks never
  create their own socket — they interact through this service.

Key behaviours:

  1. connect(token)
     Creates a socket.io-client Socket connected to SOCKET_URL with:
       - transports: ['websocket']   (no long-polling; as required by server)
       - auth: { token }             (JWT passed in handshake auth object)
       - reconnection: false         (manual reconnection for token refresh)
       - timeout: 90_000             (accounts for Render free-tier cold start)

  2. Server event → socketStore
     After connecting, attaches listeners for all 5 server events and routes
     them to the appropriate Zustand action in socketStore:
       - message.created   → store.pushIncomingMessage()
       - presence.changed  → store.applyPresenceChanged()
       - typing.started    → store.applyTypingStarted()
       - typing.stopped    → store.applyTypingStopped()
       - receipt.delivered } (registered but left for screens/hooks to handle
       - receipt.read      }  via query invalidation)

  3. connect_error + disconnect handling
     When the server closes the socket (token expired or invalid):
       a. Reads refreshToken from authStore.
       b. Calls POST /auth/refresh directly (without apiClient to avoid
          circular dependency).
       c. On success: saves the new token and reconnects after 1 second.
       d. On failure: calls clearSession() to send the user to login.

  4. emit(event, payload)
     Returns a Promise<AckResponse> for all client commands that require
     acknowledgement (presence.subscribe, presence.unsubscribe,
     typing.start, typing.stop).

  5. disconnect()
     Removes all listeners, calls socket.disconnect(), and sets
     socketStore.connected = false.

NEW FILE: src/core/store/socketStore.ts
────────────────────────────────────────────────────────────────────────────────

Purpose:
  An in-memory Zustand store (NOT persisted to MMKV) that holds the
  current real-time state for the app. It is updated exclusively by
  socketService and read by hooks/screens.

State shape:

  connected: boolean
    Whether the socket is currently connected.

  conversations: Record<conversationId, ConversationRealtimeState>
    A map from conversation ID to:
      - participants: ParticipantPresence[]   (userId + status online/offline)
      - typing: TypingUser[]                  (userId + expiresAt ISO string)
    Populated after a successful presence.subscribe acknowledgement.

  incomingMessages: Record<conversationId, MessageCreatedEvent[]>
    Accumulates message.created events from the socket so ChatDetailScreen
    can merge them into the React Query cache. Cleared after consumption.

Actions:
  setConnected(bool)
  subscribeConversation(id, { participants, typing })
  unsubscribeConversation(id)
  applyPresenceChanged(event)   — updates a single participant's status
  applyTypingStarted(event)     — upserts a TypingUser entry
  applyTypingStopped(event)     — removes a TypingUser entry
  pushIncomingMessage(event)    — appends (deduplicates by id)
  clearIncomingMessages(id)     — called by ChatDetailScreen after merge

NEW FILE: src/core/providers/SocketProvider.tsx
────────────────────────────────────────────────────────────────────────────────

Purpose:
  A React component (no UI, side-effects only) that manages the socket
  connection lifecycle in response to auth state changes.

How it works:
  - Subscribes to accessToken from authStore via Zustand selector.
  - useEffect runs whenever accessToken changes:
      If accessToken is truthy  → socketService.connect(accessToken)
      If accessToken is null    → socketService.disconnect()
  - On unmount (app teardown)  → socketService.disconnect()

This means:
  - The socket connects automatically the moment the user logs in and
    tokens are saved.
  - The socket disconnects immediately when the user logs out and
    clearSession() is called.
  - If the token is silently refreshed, SocketProvider re-runs and
    reconnects with the new token.

    → maps the API user shape to the local User shape.
  - Because accessToken is now set, SocketProvider picks it up and
    socketService.connect() is called automatically.

     (errors are swallowed so the user is always logged out locally).

  Body: { clientMessageId, text }

NEW FILE: src/features/home/hooks/useConversationRealtime.ts
────────────────────────────────────────────────────────────────────────────────

Purpose:
  Custom hook that manages the real-time presence and typing subscription
  for a single conversation screen.

Lifecycle:
  - On mount: emits presence.subscribe to the server via socketService.emit().
    On acknowledgement, saves the initial participants and typing list into
    socketStore via subscribeConversation().
  - On unmount: emits presence.unsubscribe and calls unsubscribeConversation()
    to clean up the socketStore entry.

Returns:
  participants: ParticipantPresence[]
    Live list of { userId, status } for every participant in the conversation.

  typingUsers: TypingUser[]
    Live list of { userId, expiresAt } for users currently typing.

  startTyping()
    Emits typing.start. Should be called on every text change while there
    is content. A real app refreshes this every ~3 seconds while the user
    keeps typing (the server expires typing after 5 seconds).

  stopTyping()
    Emits typing.stop. Called on text clear or input blur.

      Persisted to MMKV via Zustand persist middleware.

      Transient OTP challenge ID passed from LoginScreen to VerifyScreen.
      Persisted (so it survives a quick background/foreground), but
      always cleared after a successful verify.

      Called by useVerifyOtp on successful login.

      Called by apiClient's refresh interceptor and socketService
      after a silent token refresh.

    setChallengeId(id | null)
      Called by LoginScreen (set) and VerifyScreen (clear).

    clearSession()
      Resets user, accessToken, refreshToken, and challengeId to null.
      Called by useLogout and on refresh failure.

MODIFIED FILE: src/features/home/screens/ChatDetailScreen.tsx
────────────────────────────────────────────────────────────────────────────────

This file was rewritten to add full real API + real-time integration.
The visual design and media panel are preserved.

New imports:
  useLocalSearchParams  — reads the conversationId from the URL (/chats/:id)
  useAuthStore          — to get currentUserId for isMe detection
  useMessages           — loads message history
  useSendMessage        — sends new messages
  useMarkDelivered      — marks incoming messages as delivered
  useMarkRead           — marks incoming messages as read
  useConversationRealtime — presence + typing subscription
  useSocketStore        — reads incomingMessages[] for live updates
  queryClient           — used to update the message cache on socket events

Key changes:

  1. Message loading
     useMessages(conversationId) fetches the real history.
     An ActivityIndicator is shown while messagesLoading is true.

  2. Real-time message appending
     A useEffect watches socketStore.incomingMessages[conversationId].
     When new messages arrive via the socket, they are merged into the
     React Query cache via queryClient.setQueryData() and the raw events
     are cleared from socketStore via clearIncomingMessages().

  3. Auto mark delivered + read
     A useEffect runs whenever serverMessages.length changes.
     It finds the last message from another user and calls both
     markDelivered.mutate() and markRead.mutate() automatically.

  4. Auto-scroll
     A FlatList ref scrolls to the bottom whenever messages update.

  5. Typing indicator
     - handleTextChange() calls startTyping() when there is text.
     - TextInput.onBlur() calls stopTyping().
     - A ListFooterComponent renders three bouncing dots when
       isOtherTyping is true (detected from typingUsers in socketStore).

  6. Send button
     Calls sendMessage.mutate({ conversationId, text }) on press.
     Disabled and shows ActivityIndicator while isPending.
     Clears the TextInput immediately (optimistic UX).

  7. Online indicator in header
     isOtherOnline is derived from the participants[] in socketStore.
     The AvatarWidget's isOnline prop and the subtitle text
     ("Online" / "Offline") are driven by live presence data.

  8. isMe detection
     Messages are rendered on the right (blue bubble) if
     item.senderId === currentUserId, otherwise on the left (white).
